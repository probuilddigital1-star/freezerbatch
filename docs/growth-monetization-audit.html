01 / Executive verdict

Own the freezer-safe hosting workflow

Competing as a generic batch calculator creates a feature race. The defensible category is a complete hosting system: calculate, verify, shop, label, store, serve, and share.

Recommended positioning

The freezer-safe hosting system for cocktails that are ready before the guests arrive.

Business model principle
Keep the calculator free. Monetize the event around it.

Free utility drives discovery and sharing. Host planning, exports, labels, bundles, and high-intent product recommendations create revenue.

✓

Real utility

The calculator solves ABV, dilution, bottle size, and freezer-readiness questions.

✓

Clear niche

“Make it early, pour it later” is a sharper promise than generic batch scaling.

✓

Expandable foundation

Astro, structured recipe data, and static delivery can support efficient content growth.

02 / Critical findings

The leaks suppressing growth

These are ordered by compounding impact. The first three affect every future acquisition and monetization experiment.

The apex and www domains serve different products

Critical

The apex domain serves the current dark, 18-recipe site. The www host serves an older light experience with different navigation, calculations, and content. Meanwhile, automated emails still generate www links.

  • Search equity and backlinks are split across two site generations.
  • Subscribers are sent into an obsolete experience.
  • Analytics, conversion attribution, and recipe claims become unreliable.
public/_redirects:5 n8n/FreezerBatchCocktails.json:25 Apex page ↗ WWW page ↗

Shared links do not restore the shared recipe

Critical

Sharing writes recipe state into URL parameters, but calculator initialization never reads those parameters. A recipient can open a link without seeing the sender’s actual calculation—the core viral promise fails at the handoff.

  • Introduce a validated, versioned share-state format.
  • Send presets to canonical recipe URLs and custom plans to compact share URLs.
  • Generate a branded preview card and track creation versus recipient activation.
src/components/Calculator.astro:602 src/components/Calculator.astro:1440

Email and custom inputs need security hardening

Critical

User-controlled ingredient values flow into browser HTML and HTML email templates. The public email webhook also lacks visible rate limits, bot controls, and strict schema enforcement.

  • Replace HTML string construction with safe DOM APIs and escape all email values.
  • Separate transactional recipe delivery from newsletter consent and CRM state.
  • Add Turnstile, rate limits, request validation, size caps, and a branded sender.
  • Repair workflow branching so unsubscribe actions cannot also trigger welcome mail.
src/components/Calculator.astro:1272 n8n/FreezerBatchCocktails.json:77

Recipe pages lack the media and metadata that drive discovery

High

Recipe structured data has no image, every page uses the same generic SVG social asset, and guides lack Article metadata, authorship, dates, and original imagery. That limits rich-result eligibility, social click-through, and trust.

  • Create original 1:1, 4:3, 16:9, and vertical 2:3 imagery for every core recipe.
  • Add Recipe images, ItemList markup, Article schema, named authors, and test dates.
  • Use truthful modification dates in one canonical sitemap.
src/pages/cocktails/[slug].astro:68 src/layouts/Layout.astro:24 src/pages/sitemap-index.xml.ts:22 Google Recipe docs ↗ Pinterest Recipe Pins ↗

Storage claims contradict the underlying recipes

High

Citrus and coffee recipes are labeled “bulletproof,” which can render “Lasts months” alongside guidance such as “Best within a week” or “2–3 weeks.” Remaining liquid and preserving peak flavor are different promises.

  • Replace the Boolean with explicit freezer safety and best-quality duration fields.
  • Capture separation risk, reshake requirements, storage reason, and tested ABV.
  • Consolidate JSON, calculator constants, glass mappings, and recipe names into one schema.
src/data/cocktails.json src/lib/calculator.ts src/components/Calculator.astro:1166

The test report no longer reflects the current site

Medium

Forty-seven Playwright tests exist, but the main test command invokes Vitest and the browser suite still expects the old hero, navigation, card selectors, and calculator defaults. At least 17 failures accumulated before the audit run timed out.

  • Separate unit and browser test commands.
  • Add share restoration, consent-state, schema, and revenue-event coverage.
  • Gate deployment on type checking, production build, smoke tests, and link checks.

04 / Monetization stack

Monetize outcomes, not the basic math

Revenue should follow user intent. Someone planning a party has a more valuable problem than someone checking one ratio, so build around the event and its purchase decisions.

Primary product revenue

Paid Host Mode

A premium planning layer for people preparing multiple drinks, purchasing supplies, or hosting a meaningful event. Prefer a clear one-time purchase or event pass before introducing subscription complexity.

  • Scale by guests, servings, or total target volume
  • Multi-cocktail menu with consolidated shopping list
  • Cost per drink, inventory constraints, and leftover estimates
  • Printable labels, QR menus, schedule, and PDF export
Why it wins It monetizes the high-value hosting outcome without weakening the free acquisition engine.

Commerce revenue

Contextual barware bundles

Replace generic affiliate grids with recipe- and task-specific recommendations. Verify the current affiliate tag, audit every ASIN, and attribute clicks by recipe, placement, product, and source.

  • “Everything needed for this batch” modules
  • Freezer bottle, funnel, label, jigger, and glassware guides
  • Budget, durable, and gift-quality bundle options
  • Deep links to StockTheEvent with campaign attribution
Economic signal Amazon currently lists Kitchen at 4.5% and alcoholic beverages at 0%; prioritize tools, not liquor.

Owned-audience revenue

Digital playbooks & lifecycle email

Turn recipe delivery into an event-completion sequence. Pair it with concise paid assets that save planning time rather than simply repackaging free recipes.

  • Freezer Bar Starter Pack and printable bottle-label bundle
  • Wedding, holiday, Thanksgiving, and summer hosting playbooks
  • Shopping reminder, storage reminder, and related-menu sequence
  • Host Mode offer only after the requested recipe is delivered
Why it compounds Email becomes a return channel, a conversion surface, and a source of seasonal demand.

Scale-stage revenue

Sponsorships & display ads

Introduce ads only after traffic is material, trust is established, and page-speed impact is measured. Direct sponsorship from barware, mixer, and non-alcoholic brands is likely more aligned than broad alcohol brand deals.

  • Protect calculator interaction and core recipe readability
  • Use a certified consent platform where legally applicable
  • Keep sponsorship claims transparent and editorially independent
Timing Journey by Mediavine begins consideration above 1,000 sessions, subject to quality and brand-safety review.
Affiliate reality Tools, bottles, glassware, labels, and books carry the value. Liquor itself is not an attractive Amazon commission category. Amazon schedule ↗
Advertising constraint Educational cocktail content is generally monetizable, while alcohol sales promotion and misuse content face restrictions. Google policy ↗

Repair the engine, then accelerate it

The sequence matters. Search content, creator outreach, and ads should follow—not precede— the fixes that let traffic convert, share, return, and generate attributable revenue.

P1 · Convert Working shares. Trustworthy data. Analytics. Weeks 2–4
P2 · Differentiate Host planning, labels, imagery, and saves. Weeks 4–8
P3 · Scale Paid mode, embeds, Pinterest, and content. Weeks 7–12

Days 1–7 Unify the public experience Redirect www to apex, update all email links and sender identity, repair unsubscribe and marketing-consent paths. Recover search authority, brand trust, and reliable conversion paths.
Days 1–10 Make sharing safe and functional Restore validated URL state, remove injection paths, rate-limit the webhook, and add automated share-link coverage. Unlock the core recipient-acquisition loop without increasing abuse risk.
Week 2 Instrument the funnel Track calculation completion, sharing, recipient activation, email, affiliates, cross-site referrals, and purchases. Establish a baseline for growth and revenue decisions.

Weeks 6–9 Launch initial revenue products Introduce Host Mode, a starter digital bundle, and contextual affiliate kits with end-to-end attribution. Validate willingness to pay and the highest-value commerce placements.
Weeks 8–12 Scale distribution Publish event-focused content, launch the publisher embed, build the Pinterest cadence, and add recipient/referral lifecycle email. Build compounding search, social, backlink, and word-of-mouth acquisition.

07 / Technical appendix

Evidence and implementation notes

The audit covered the repository, production host behavior, calculator state flow, structured data, email automation, monetization surfaces, and the automated test inventory.

Repository profile

  • Astro 4 with Tailwind and static Cloudflare Pages delivery
  • 18 recipes in src/data/cocktails.json
  • Large calculator web component in src/components/Calculator.astro
  • Four hardcoded editorial guides and a custom dynamic sitemap
  • n8n, Resend, and Google Sheets email/CRM automation

Monetization profile

  • Affiliate product mappings exist for all 18 recipe pages
  • Homepage Amazon links are generic and lack placement attribution
  • The default affiliate tag should be verified as project-owned
  • StockTheEvent referrals need UTM and conversion continuity
  • No event-level revenue analytics were found in the repository

SEO & trust profile

  • Recipe markup exists but lacks required imagery
  • Generic Open Graph image is reused site-wide
  • No named recipe tester, reviewer, test date, or correction log
  • Current-date sitemap modification values are not meaningful
  • Google recommends original work, clear authorship, and first-hand expertise
People-first guidance ↗

Quality profile

  • npm test points Vitest at Playwright-style suites
  • Browser coverage contains substantial stale UI expectations
  • Core calculator math still has useful passing coverage
  • The existing 47/47 QA report predates the current redesign
  • The production build could not be independently validated in the restricted audit environment
Recommended decision

Do not buy growth yet. Make every acquired visitor compound first.

Spend the next 30 days unifying the product, repairing the share and email loops, instrumenting outcomes, and publishing credible media. Then ship Host Mode and scale Pinterest, occasion content, embeds, and partnerships against a working funnel.
